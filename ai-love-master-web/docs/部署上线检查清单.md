# 部署上线检查清单

## 一、前端

### 1. 生产环境 API 地址
- [ ] 新增 `.env.production`，设置后端 API 地址：
  ```
  VITE_API_BASE_URL=https://你的后端域名/api
  ```
  或前后端同域时用相对路径：
  ```
  VITE_API_BASE_URL=
  ```
  （留空则请求同源）

### 2. 构建
```bash
cd frontend
npm run build
```
- 输出在 `dist/`，可部署到任意静态托管

### 3. SPA 路由
使用 `createWebHistory`，需保证**所有路径回退到 index.html**：
- Nginx: `try_files $uri $uri/ /index.html;`
- 其他静态托管需开启 SPA 回退配置

---

## 二、后端

### 1. CORS
- [ ] 生产环境允许前端域名访问 `/api/**`
- 示例：
  ```java
  // 允许 https://你的前端域名
  .allowedOrigins("https://your-frontend-domain.com")
  // 或本地调试
  .allowedOrigins("http://localhost:5175", "http://localhost:5175/")
  ```

### 2. 生产配置
- [ ] `application.yml` 或 `application-prod.yml`：
  - JWT 密钥、过期时间
  - AI 接口 Key（不要写在代码里）
  - 数据库连接（如有）
- [ ] 敏感信息用环境变量

### 3. 接口保护
- [ ] 登录/注册以外的接口需 JWT 校验
- [ ] 建议加接口限流，防止滥用

---

## 三、部署方式示例

### 方案 A：前后端同服（单机）
- 后端：`java -jar app.jar`（端口 8080）
- 前端：构建后复制 `dist/*` 到 `src/main/resources/static/`
- 或用 Nginx 同时代理 API 和静态资源

### 方案 B：前后端分离
- 前端：部署到 OSS、Vercel、Nginx 等
- 后端：部署到云服务器、容器
- 配置 CORS 和 `VITE_API_BASE_URL`

### 方案 C：Nginx 反向代理
```nginx
server {
  listen 80;
  server_name your-domain.com;

  # 前端
  location / {
    root /path/to/dist;
    try_files $uri $uri/ /index.html;
  }

  # 后端 API
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

## 四、通用

- [ ] **HTTPS**：用 Let's Encrypt 或云厂商 SSL
- [ ] **域名**：备案（国内）、解析
- [ ] **接口密钥**：AI Key 等不要提交到代码库
- [ ] **日志与监控**：生产环境开启访问/错误日志
- [ ] **测试**：线上环境完整走一遍登录 → 聊天流程
