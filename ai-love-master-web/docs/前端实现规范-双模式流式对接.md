# 恋爱大师前端双模式流式对接规范

## 重要：两个模式对应不同接口，切勿弄反

| 模式 | 用途 | 调用的接口 | 数据格式 |
|------|------|------------|----------|
| **AI恋爱大师** | 纯聊天（无工具） | `POST /api/chat/stream` | SSE 原始文本块 + conversationId 事件 |
| **超级智能体** | 聊天 + 工具调用 | `POST /api/chat/react/stream?maxSteps=8` | SSE 中每行一条 JSON，含 type 字段 |

---

## 1. AI 恋爱大师（chat/stream）

### 接口
- **路径**：`POST {{baseUrl}}/api/chat/stream`
- **请求体**：`{"message":"用户输入","conversationId":"可选，新会话可空"}`

### 响应（SSE 流）
- 大部分事件为**纯文本块**（逐 token/delta 发送）
- 最后一条事件名 `conversationId`，data 为会话 ID

### 后端数据流
```
streamingChatModel.stream(prompt)
  → Flux<String>（每项为 delta）
  → Controller subscribe → emitter.send(chunk) 逐字输出
```

### 前端展示
- 逐字打字机效果，无需解析 JSON
- 每收到一个 chunk 即 `onChunk(chunk)` 追加到 typing 内容

---

## 2. 超级智能体（chat/react/stream）

### 接口
- **路径**：`POST {{baseUrl}}/api/chat/react/stream?maxSteps=8`
- **请求体**：同上 `{"message":"用户输入","conversationId":""}`

### 响应（SSE 流）
- 每行一条 JSON 对象，格式如：`data: {"type":"xxx", ...}`

### 事件类型及含义

| type | 含义 | 典型字段 | 展示建议 |
|------|------|----------|----------|
| start | 连接成功 | content | 可选展示或忽略 |
| conv | 会话 ID | conversationId | 保存供后续请求使用 |
| thought | 思考过程 | content | 展示思考区域 |
| tool_call | 调用工具 | content, toolName, toolInput | 展示「正在调用 xxx」 |
| tool_result | 工具结果 | content | 展示工具返回摘要 |
| reply | 最终回复 | content | **按序追加，实现打字机效果** |
| error | 错误 | content | 展示错误提示 |

### reply 流式分片（重要）

**reply 会被多次以 chunk 形式发送。** 后端在无工具路径下使用 `streamingChatModel.stream(messages)`，每个 delta 通过 `stepConsumer({"type":"reply","content":chunk})` 推送。

- 前端应**按顺序**对每次 `type:"reply"` 的 `content` 进行**追加以呈现打字机效果**
- 示例：依次收到 `{"type":"reply","content":"你"}`、`{"type":"reply","content":"好"}` → 最终展示「你好」
- 当前实现：`typewriter.feed(ev.content)` 在 `useStreamTypewriter` 中累积 `receivedContent += s`，按序追加后通过 tick 逐字显示

### 后端数据流（无工具路径）
```
streamingChatModel.stream(messages)
  → doOnNext(chunk → stepConsumer({"type":"reply","content":chunk}))
  → blockLast() 阻塞到流结束
  → memoryStore.add
```

### 前端展示
- 按 type 分别渲染 thought、tool_call、tool_result、reply 等区域
- reply：使用 `useStreamTypewriter`，每收到 reply chunk 调用 `feed(content)`，实现分步流式展示

---

## 3. 检查清单（避免弄反）

- [ ] 「AI恋爱大师」入口 → 调用 `/api/chat/stream`
- [ ] 「超级智能体」入口 → 调用 `/api/chat/react/stream`
- [ ] 两个接口的 fetch / ReadableStream 逻辑分开，不要混用
- [ ] reply 事件按序追加，不覆盖、不乱序
